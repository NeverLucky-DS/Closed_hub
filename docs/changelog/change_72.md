# change_72 — Порог cosine similarity и поиск файлов на сайте

## Что изменено

### 1. Порог cosine distance в семантическом поиске (`db/repo.py`)
- В `semantic_search_resource_links` и `semantic_search_library_files` добавлен параметр `max_distance=0.65`.
- SQL: `WHERE ... AND (embedding <=> $1::vector) <= $3` — результаты с расстоянием > 0.65 (similarity < 0.35) отсекаются.
- Нерелевантные материалы (не упомянутые в запросе) больше не попадают в выдачу.

### 2. Fallback на ILIKE при пустой семантической выдаче
Во всех caller'ах: `bot/handlers/library_cmd.py`, `bot/handlers/messages.py`, `web/app.py`:
- Если semantic search вернул пустой список (все результаты отсеяны порогом), автоматически выполняется ILIKE-поиск.
- Это гарантирует, что точный поиск по имени автора/ключевому слову всегда работает.

### 3. Поиск по файлам на странице `/library` (`web/app.py`, `web/templates/library.html`)
- `GET /library?q=...` теперь возвращает `view='search'` с результатами поиска по всем файлам.
- Используется семантический поиск (с порогом) с fallback на ILIKE.
- В `library.html` добавлены: форма поиска (всегда наверху), блок `view == 'search'` с карточками файлов.
- Переход `{% if view == 'folders' %}` → `{% if view == 'search' %} / {% elif view == 'folders' %} / {% else %}`.

## Обоснование
Без порога семантический поиск ранжирует *все* материалы от лучшего к худшему, возвращая нерелевантные результаты. Порог 0.65 (similarity ≥ 0.35) даёт разумный баланс: релевантные материалы проходят, а случайно совпавшие по смежным темам — нет. Fallback на ILIKE обеспечивает работу точных имён/терминов, когда embedding не помогает.
