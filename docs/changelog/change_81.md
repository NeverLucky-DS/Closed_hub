# change_81 — Ужесточение путей библиотеки и блокировка запросов к `.env`

## Что изменено

- `move_into_category_folder`: каталог назначения всегда через `slugify_folder`, проверки `resolve()` и `is_relative_to` для корня библиотеки, исходного файла и файла назначения; имя файла только через `Path(...).name`.
- `finalize_file_to_library`: нормализация `slug` через `slugify_folder`, при небезопасном пути — отказ без исключения наружу.
- Подтверждение загрузки на сайте: для выбора категории без «своей папки» slug так же прогоняется через `slugify_folder`.
- В HTTP middleware: ответ `404` на пути, похожие на доступ к `.env` или `.git/` (чтобы случайный маршрут или прокси не отдавали секреты).

## Обоснование

Доверенные участники не отменяют риска компрометации одного аккаунта или ошибки в форме: некорректный `slug` раньше мог привести к записи вне дерева `library/` из-за особенностей `pathlib`. Явная блокировка `.env` в URL — тонкая страховка поверх того, что статика смонтирована только с `web/static` и соседних каталогов, а не из корня репозитория.
